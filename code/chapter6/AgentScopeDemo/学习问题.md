● 代码已全部读完。这是一个基于 AgentScope 框架的三国狼人杀多智能体游戏。以下是从初学者到 Agent
应用开发就业方向，按知识层次整理的问题：

---

一、基础概念理解

1. 这个项目中哪些是 Agent？每个 Agent 的职责是什么？和普通的 Python 对象有什么区别？
2. ReActAgent 的 "ReAct" 代表什么？它和普通的 AgentBase 有什么区别？
3. 什么是"结构化输出"（Structured Output）？为什么投票、查验等动作需要用 Pydantic 模型来约束 LLM 的输出，而不是让 LLM
   直接返回文本？
4. DashScopeChatModel 在这里扮演什么角色？如果要换成 OpenAI 的模型，需要改哪些地方？

---

二、框架与 API 理解

5. MsgHub 的作用是什么？enable_auto_broadcast=True 和 False 分别对应什么场景？（提示：对比狼人密聊和公开投票）
6. sequential_pipeline 和 fanout_pipeline 的区别是什么？分别用在了游戏的哪些环节？
7. agent.observe() 方法做了什么？预言家查验结果后为什么要调用 observe()？
8. DashScopeMultiAgentFormatter 的作用是什么？多 Agent 场景下的消息格式和单 Agent 有什么不同？

---

三、提示词与工程设计

9. prompt_cn.py 中的提示词设计有什么优缺点？如果要在狼人白天讨论时让 Agent 展示更强的推理能力，你会如何改进提示词？
10. 代码中用 Literal[tuple(_.name for _ in agents)] 来限制投票目标只能是存活玩家。这种"运行时动态生成
    Schema"的技巧在实际 Agent 开发中有哪些应用场景？
11. 狼人阵营需要密谋，但 DiscussionModelCN 是所有角色共用的。实际开发中，你会如何为不同角色设计不同的结构化输出？

---

四、系统设计与工程能力

12. 游戏的状态管理（alive_players、werewolves、药水状态等）分布在 ThreeKingdomsWerewolfGame
    类中。如果要支持断线重观或游戏回放，你会如何重构状态管理？
13. check_winning_cn() 在每个阶段结束后检查胜利条件。这种"轮询式检查"有什么局限？如果游戏规模扩大到 20
    人，你会如何优化？
14. 异步编程在这个项目中为什么是必要的？如果去掉所有 async/await 改成同步代码，会出什么问题？
15. GameModerator 继承了 AgentBase 但它自己不做 LLM 调用。为什么要这样设计？直接用一个普通类不行吗？

---

五、Agent 面试高频问题

16. 多 Agent 协作模式：这个项目展示了哪些多 Agent 间的通信模式？（提示：广播、点对点、投票聚合）对比一下 AutoGen 或
    CrewAI 的协作模式。
17. 幻觉与可靠性：LLM 可能不按 JSON 格式回复，代码中做了哪些防御？还有什么更好的方案？（提示：重试、校验、Function
    Calling）
18. 成本控制：每个 Agent 每轮都要调用 LLM，6 人游戏一轮下来要调用多少次 API？如何优化 Token 消耗？
19. 可观测性：GameModerator 记录了 game_log，但缺少结构化的 trace。如果要接入 LangSmith
    或类似的可观测平台，你会怎么做？
20. 从 Demo 到产品：这个狼人杀 Demo 要做成线上可玩的产品，你需要补齐哪些工程能力？（并发、持久化、前端交互、安全）
