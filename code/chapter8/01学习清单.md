01_MemoryTool_Basic_Operations 学习问题清单

一、基础概念理解（面试常问）

1. 为什么 Agent 需要记忆系统？

▎ 如果没有记忆，Agent 每次对话都是"失忆"状态。想想看：一个客服 Agent 记不住用户之前说过什么，会导致什么问题？

2. 四种记忆类型分别对应人类认知的哪些能力？

▎ 代码中出现了 working（工作记忆）、episodic（情景记忆）、semantic（语义记忆）、perceptual（感知记忆）。请用自己的话解
▎ 释每种记忆存什么、什么时候用。

3. working 记忆和 episodic 记忆的核心区别是什么？

▎ 代码里往两种记忆都存了内容，但它们的生命周期和用途完全不同。你能说清楚吗？

4. importance 参数的作用是什么？为什么是 0~1 的浮点数？

▎ 代码中添加记忆时设置了 importance:0.7、0.8、0.9 等值。这个分数会影响什么行为？

---

二、代码实操理解（动手能力）

5. memory_tool.run() 的参数结构是怎样的？

▎ 观察代码中所有的 run() 调用，总结它的参数模式。为什么用 dict 传参而不是函数参数？

6. 搜索时的三个过滤维度分别是什么？

▎ search_memory_demo 函数中展示了三种搜索方式：基础搜索、按类型搜索、按重要性阈值搜索。它们各自的适用场景是什么？

7. forget 操作的 strategy 参数意味着什么？

▎ 代码中用了 importance_based 策略。如果让你设计，还能想到哪些遗忘策略？（提示：想想人类是怎么遗忘的）

8. consolidate 操作模拟了什么认知过程？

▎ 代码把 working 记忆整合到 episodic 记忆，设置了 importance_threshold:0.6。这个过程在神经科学中叫什么？

三、架构设计思维（进阶面试题）

9. 为什么用统一的 run() 接口而不是暴露 add()、search() 等独立方法？

▎ 这涉及到设计模式。想想 Agent 框架中 Tool 的通用调用方式，这样设计有什么好处？

10. 如果让你给这个 MemoryTool 增加持久化功能，你会怎么做？

▎ 目前代码运行后数据存在内存中，程序结束就没了。要支持"下次启动还能记住"，需要改哪些地方？

11. user_id 参数的设计意图是什么？

▎ 如果系统同时服务 1000 个用户，user_id 起到什么作用？这涉及到什么架构概念？

12. 四种记忆类型可以只启用部分吗？

▎ 初始化时传了全部四种，如果某个场景只需要语义记忆，应该怎么设计？这体现了什么设计原则？

四、就业实战方向（综合应用）

13. 如果你面试时被问"请设计一个有记忆能力的客服 Agent"，你会怎么用这个 MemoryTool？

▎ 提示：客服场景中，哪些信息应该存为 working memory？哪些应该是 episodic？哪些是 semantic？

14. 这个记忆系统有什么局限性？

▎ 想想：当记忆条数达到百万级时，搜索性能会怎样？importance 评分由谁来决定？自动评分还是用户手动？

15. 和 RAG（检索增强生成）相比，这种记忆系统的优势和劣势分别是什么？

▎ 这是 Agent 面试高频题。两者都能让 Agent "记住"信息，但机制完全不同。
