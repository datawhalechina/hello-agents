# RAG (Retrieval-Augmented Generation) 过程详解

## 一、核心概念

RAG 的核心流程：**文档 → 分块 → 嵌入 → 检索 → 生成**



```
┌─────────────────────────────────────────────────────────────────┐
│                         RAG 完整流程                            │
├────────────────────────────────────────────────────────────────┤
│                                                                │
│  1. 文档加载 (Document Loading)                                 |
│     ┌─────────────┐    ┌─────────────┐    ┌─────────────┐      │
│     │   PDF       │    │  Markdown   │    │    HTML     │      │
│     └──────┬──────┘    └──────┬──────┘    └──────┬──────┘      │
│            └─────────────────┬─────────────────┘               │
│                              ↓                                 │
│                      ┌───────────────┐                         │
│                      │  MarkItDown   │  (统一转换为Markdown)    │
│                      └───────┬───────┘                         │
│                              ↓                                 │
│                      ┌───────────────┐                         │
│                      │    纯文本      │                         │
│                      └───────────────┘                         │
│                                                                │
│  2. 分块 (Chunking) -- 一般做俩步分块(语义/结构化)  再来做token字符数分块 │
│     ┌─────────────────────────────────────────────────────┐    │
│     │  参数配置:                                           │    │
│     │  • chunk_size: 1000  (每块约1000字符)                │    │
│     │  • chunk_overlap: 200 (相邻块重叠200字符)            │    │
│     └─────────────────────────────────────────────────────┘    │
│                              ↓                                 │
│     ┌──────────────┐  ┌──────────────┐  ┌──────────────┐       │
│     │   Chunk 1    │  │   Chunk 2    │  │   Chunk 3    │       │
│     │  [0-1000]    │  │  [800-1800]  │  │ [1600-2600]  │       │
│     │   ↑重叠200↑  │  │   ↑重叠200↑  │  │              │        │
│     └──────┬───────┘  └──────┬───────┘  └──────┬───────┘       │
│            └─────────────────┼─────────────────┘               │
│                              ↓                                 │
│  3. 嵌入 (Embedding)                                           │
│     Chunk 1 ──→ [0.23, -0.15, 0.88, ..., 0.12]  (384维向量)    │
│     Chunk 2 ──→ [0.88, 0.12, -0.33, ..., 0.91]                 │
│     Chunk 3 ──→ [0.15, 0.67, 0.22, ..., -0.08]                 │
│                              ↓                                 │
│     存入向量数据库 (Qdrant) - 每个Chunk是一条独立记录            │
│                                                                │
│  4. 检索 (Retrieval)                                           │
│     用户Query: "什么是注意力机制？"                              │
│                    ↓ 向量化                                     │
│     Query向量: [0.18, -0.22, 0.91, ..., 0.08]                   │
│                    ↓                                           │
│     ┌─────────────────────────────────────────────────────┐    │
│     │          向量相似度计算 (余弦相似度)                  │    │
│     │                                                     │    │
│     │   Chunk A3 (注意力机制详解):  相似度 0.92 ✓          │     │
│     │   Chunk A4 (多头注意力):     相似度 0.88 ✓           │     │
│     │   Chunk A1 (Transformer简介): 相似度 0.85 ✓          │     │
│     │   Chunk B1 (CNN卷积):       相似度 0.32              │     │
│     │   Chunk B2 (池化层):        相似度 0.15              │     │
│     │                                                     │     │
│     │   返回 top_k=3: [A3, A4, A1]  ← 最相似的CHUNKS!      │     │
│     └─────────────────────────────────────────────────────┘     │
│                              ↓                                  │
│  5. 生成 (Generation)                                            │
│     将检索到的Top-K Chunks作为上下文 → 送给LLM生成答案             │
│                              ↓                                  │
│     "注意力机制是Transformer的核心组件，它允许模型..."             │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 二、分块策略详解

### 2.1 分块参数

```python
result = self.rag_tool.run({
    "action": "add_document",
    "file_path": pdf_path,
    "chunk_size": 1000,      # 每块大约1000个字符
    "chunk_overlap": 200     # 相邻块之间重叠200个字符
})
```


##  一般是语义分块 再做 固定大小分块！！！  -- 俩步分块, 这里也能做结构化分块，分块策略可以不同！！！
## 先按标题结构或语义来分割文本，再按块来切，《避免在标题处切断 丢失上下文》

标准Markdown文本 → 标题层次解析 → 段落语义分割 → Token计算分块 → 重叠策略优化 → 向量化准备
       ↓                ↓              ↓            ↓           ↓            ↓
   统一格式          #/##/###        语义边界      大小控制     信息连续性    嵌入向量
   结构清晰          层次识别        完整性保证    检索优化     上下文保持    相似度匹配




### 2.2 分块策略对比

| 策略 | 说明 | 适用场景 |
|------|------|---------|
| **固定大小分块** | 按字符数/Token数切割 | 通用场景，简单直接 |
| **重叠分块** | 相邻块有重叠部分 | 避免上下文断裂 |
| **语义分块** | 按段落/标题分割 | 保持语义完整性 |
| **递归分块** | 先按大边界再按小边界 | 结构化文档 |


## 三、向量数据库中的存储结构

每个 **Chunk** 在 Qdrant 中是一条独立记录：

```json
{
    "id": "chunk_uuid_001",
    "vector": [0.23, -0.15, 0.88, 0.12, -0.56, ...],
    "payload": {
        "content": "Transformer的核心是自注意力机制...",
        "memory_type": "rag_chunk",
        "document_id": "doc_001",        // 所属原始文档
        "chunk_index": 0,                // 这是第几个块
        "rag_namespace": "default",
        "title": "Transformer架构详解",
        "total_chunks": 5
    }
}
```

**关键点**：向量库里存的是 **Chunks**，不是原始文档！

## 四、检索过程详解

### 4.1 搜索函数解析

```python
def search_vectors_expanded(
    query: str = "",
    top_k: int = 8,           # 返回最相似的8个CHUNKS（不是文档）
    candidate_pool_multiplier: int = 4,  # 候选池倍数
    enable_mqe: bool = False, # 多查询扩展
    enable_hyde: bool = False, # 假设文档嵌入
    ...
) -> List[Dict]:
    # 1. 查询扩展（可选）
    expansions = [query]
    if enable_mqe:
        expansions.extend(_prompt_mqe(query, mqe_expansions))
    if enable_hyde:
        expansions.append(_prompt_hyde(query))
    
    # 2. 计算候选池大小
    pool = max(top_k * candidate_pool_multiplier, 20)  # 8*4=32
    per = max(1, pool // len(expansions))  # 每个查询分配的检索数
    
    # 3. 对每个扩展查询进行向量检索
    agg = {}
    for q in expansions:
        qv = embed_query(q)  # 查询向量化
        hits = store.search_similar(
            query_vector=qv,
            limit=per,         # 每个查询返回per个结果
            ...
        )
        # 4. 合并结果（按chunk ID去重，保留最高相似度）
        for h in hits:
            mid = h.get("metadata", {}).get("memory_id")  # CHUNK的ID
            s = float(h.get("score", 0.0))
            if mid not in agg or s > float(agg[mid].get("score", 0.0)):
                agg[mid] = h
    
    # 5. 按相似度排序，返回top_k个CHUNKS
    merged = list(agg.values())
    merged.sort(key=lambda x: float(x.get("score", 0.0)), reverse=True)
    return merged[:top_k]  # ← 返回的是CHUNKS！
```

## 五、常见困惑解答

### Q1: 返回的是 top-k 文档还是 top-k 块？

**答**：返回的是 **top-k 个 Chunks（块）**！

```
❌ 错误理解：每个文档搜top-k，返回k个文档
✅ 正确理解：全局搜最相似的k个chunks，可能来自不同文档
```

### Q2: 如果想每个文档只返回一个最相关的块怎么办？

需要自己聚合：

```python
def search_per_document(query: str, top_k_per_doc: int = 2):
    # 1. 多召回一些chunks
    chunks = search_vectors_expanded(query, top_k=20)
    
    # 2. 按document_id分组
    doc_chunks = {}
    for chunk in chunks:
        doc_id = chunk["metadata"]["document_id"]
        if doc_id not in doc_chunks:
            doc_chunks[doc_id] = []
        doc_chunks[doc_id].append(chunk)
    
    # 3. 每个文档只取top-k个chunks
    result = {}
    for doc_id, chunks in doc_chunks.items():
        result[doc_id] = chunks[:top_k_per_doc]
    
    return result

# 结果示例：
{
    "doc_001": [chunk_A3(0.92), chunk_A4(0.88)],  # Transformer文档
    "doc_002": [chunk_B1(0.45)]                    # CNN文档
}
```

### Q3: 相似度分数怎么算？

**余弦相似度**：
```
cosine_similarity(A, B) = (A·B) / (||A|| × ||B||)
                        = 向量点积 / (向量A模长 × 向量B模长)
                        
取值范围: -1 ~ 1（通常RAG中会归一化到0~1）
```

## 六、高级检索策略

| 策略 | 缩写 | 原理 | 适用场景 |
|------|------|------|---------|
| **多查询扩展** | MQE | LLM生成多个语义等价查询，并行检索后合并 | 提高召回率 |
| **假设文档嵌入** | HyDE | LLM先生成假设答案，用答案向量检索 | 复杂问题 |
| **混合检索** | Hybrid | 向量相似度 + 关键词匹配(BM25) | 精确匹配+语义匹配 |
