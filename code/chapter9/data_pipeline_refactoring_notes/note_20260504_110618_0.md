1. **结论**  
   业务逻辑层重构时机已成熟，应基于已稳定的数据模型层，采用**接口隔离+逐步替换**策略启动重构，优先建立测试护栏，避免回归风险。

2. **依据**  
   - 数据模型层已完成重构且测试覆盖率85%，表明底层数据访问契约已稳定，可以支撑上层业务逻辑的抽象和测试。  
   - 项目当前状态标记为“数据模型层重构完成”，下一阶段自然推进到业务逻辑层。  
   - 通用重构原则：在重构高层模块前，首先确保底层模块接口清晰、行为可验证（此处已具备）。

3. **风险与假设**  
   - **假设**：数据模型层对外接口在重构期间不会发生破坏性变更；若变更，业务逻辑改造会连带返工。  
   - **风险**：业务逻辑层可能长期未整理，存在大量未覆盖的边界场景和隐式依赖；直接重构可能引入新缺陷。  
   - **风险**：团队对业务理解深度不足时，可能错误简化或遗漏规则。

4. **下一步行动建议**  
   - **梳理依赖**：列出业务逻辑模块与数据模型层的调用图，识别高耦合点及可独立拆分的模块。  
   - **建立安全网**：为待重构的关键业务逻辑补充特征测试（Characterization Tests），验证现有行为。  
   - **接口抽象**：定义业务逻辑的输入/输出接口，使其依赖抽象而非具体数据模型实现，便于单元测试。  
   - **分块重构**：按业务领域拆分功能块，逐块迁移到新实现，每完成一块即运行全量测试并部署验证。  
   - **监控对齐**：重构期间同步比对旧逻辑与新逻辑的输出，确保业务一致性。
