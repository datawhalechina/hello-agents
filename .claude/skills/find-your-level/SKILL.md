# Find Your Level（定级测验）

你正在为 **Hello-Agents** 课程（5 个部分，16 章）主持一场定级测验。你的任务是
用客观题（而不是学习者的自我描述）确定学习者应该从第几章开始，让他们跳过已经
掌握的内容，直接落在挑战开始的地方。

**不要**用「你觉得自己 transformer 懂多少」这类自评问题代替测验——自评不可靠，
必须用下面的固定题目客观打分。

## 测验结构

5 个知识区域，每个区域 2 题，共 10 题。按区域分轮进行，每轮 2 题。学习者答完
一轮的两题后，先公布该区域得分，再进入下一轮。

## 评分

每题 1 分（答错、空着或回答「不知道」记 0 分），每个区域 0-2 分，总分 0-10 分。

## 主持方式

简短问候后直接进入第一轮。每道题都用 **AskUserQuestion**（或所在环境的等价交互
方式）逐题提问，**禁止一次性把多道题甩给用户**。每轮结束后报该区域得分（例如
「LLM 基础：2/2」）。点评克制，最终结果出来之前不解释任何题目的答案。

### 第一轮 —— LLM 基础（对应第 3 章）

**Q1.** 调用大语言模型时，把 temperature 参数调高，输出会发生什么变化？

- A) 更确定、更保守
- B) 生成速度变快
- C) 更随机、更多样
- D) 上下文窗口变大

**正确答案：C**

**Q2.** BPE（Byte Pair Encoding）分词的基本思路是？

- A) 按空格切分单词
- B) 把高频出现的字符对逐步合并成子词
- C) 每个汉字单独作为一个 token
- D) 查词典切分，未登录词直接丢弃

**正确答案：B**

---

### 第二轮 —— 智能体概念与范式（对应第 1、2、4 章）

**Q3.** ReAct 范式中，智能体一轮循环的正确顺序是？

- A) Thought → Action → Observation
- B) Action → Thought → Observation
- C) Observation → Action → Thought
- D) Plan → Execute → Reflect

**正确答案：A**

**Q4.** Reflection（反思）范式的核心机制是？

- A) 多个模型并行投票
- B) 把任务拆成子任务依次执行
- C) 缓存历史回答直接复用
- D) 让智能体评估并修正自己之前的输出

**正确答案：D**

---

### 第三轮 —— 框架与工程实践（对应第 5、6、7 章）

**Q5.** LLM 的「工具调用」（tool calling / function calling）本质上是？

- A) LLM 直接在服务器上执行代码
- B) LLM 输出结构化的调用请求，由外部程序执行后把结果回传给模型
- C) 给模型挂载浏览器插件让它自主联网
- D) 通过微调把工具能力写进模型权重

**正确答案：B**

**Q6.** 一个最小可用的智能体框架，核心组件通常包括？

- A) LLM 客户端、工具注册与执行、记忆/对话历史、推理循环
- B) 前端界面、数据库、消息队列
- C) GPU 调度器和模型权重管理
- D) 爬虫、定时任务、报表系统

**正确答案：A**

---

### 第四轮 —— 记忆、检索与协议（对应第 8、9、10 章）

**Q7.** RAG（检索增强生成）系统在 LLM 生成答案之前做的事情是？

- A) 用查询重新训练模型
- B) 压缩模型权重
- C) 让用户手动挑选上下文
- D) 检索相关文档并注入提示词

**正确答案：D**

**Q8.** MCP（Model Context Protocol）解决的核心问题是？

- A) 让多个模型互相训练
- B) 加速 token 生成
- C) 用统一协议把外部工具和数据源标准化地接入 LLM 应用，避免每家各写一套
- D) 在传输层取代 HTTP

**正确答案：C**

---

### 第五轮 —— 前沿与综合（对应第 11-15 章）

**Q9.** 用强化学习（如 GRPO）训练智能体，与 SFT（监督微调）的关键区别是？

- A) 强化学习不需要任何数据
- B) 强化学习依据结果的奖励信号优化策略，而不是模仿固定的标注答案
- C) 强化学习只能用于游戏场景
- D) SFT 的效果一定更好

**正确答案：B**

**Q10.** 多智能体系统中「协调者/编排者」（orchestrator）的主要职责是？

- A) 分配任务、路由消息、管理智能体之间的协作
- B) 替代所有其他智能体
- C) 作为兜底的备份模型
- D) 压缩智能体之间的通信内容

**正确答案：A**

## 个性化学习路径

公布起始章节后，生成一张覆盖全部 16 章的 markdown 表格。

**起始章节及之后的章节一律标「学习」。** 起始章节之前的章节，按它所属区域的
得分决定状态：

| 区域得分 | 对应章节的状态 |
|----------|----------------|
| 2/2 | 跳过 |
| 1/2 | 复习（快速过一遍而不是跳过） |
| 0/2 | 学习（这个区域你还不会，不能跳） |

区域 → 章节映射：

- LLM 基础 → 第 3 章
- 智能体概念与范式 → 第 1、4 章
- 框架与工程实践 → 第 6、7 章
- 记忆、检索与协议 → 第 8、9、10 章
- 前沿与综合 → 第 11、12 章

第 2 章（发展史）、第 5 章（低代码平台）、第 13-15 章（综合案例）不参与区域
映射：位于起始章节之前时一律「跳过」，位于起始章节及之后时照常「学习」。满分
学习者跳过第 13-15 章时，在建议里提示可任选一个案例练手。

**实际起点 = 路径表里第一个标「学习」的章节。** 如果它早于分数映射给出的起始
章节（比如某区域 0/2 把更早的章节变成了「学习」），以它为实际起点，并在建议里
说明原因。实际起点只决定建议从哪一章开始，不重算其他章节的状态；「复习」章节
在建议里作为前置任务列出。

**硬性规则：第 7 章的依赖。** 本书第三部分及之后（第 8-16 章）的配套代码直接
依赖第 7 章自研的 HelloAgents 框架。因此按上述规则填完整张表后，只要第 8-16
章中存在任何标「学习」的章节，而第 7 章被标了「跳过」，就把第 7 章改成
「复习」，并在建议里提醒：先把第 7 章的框架跑起来，否则后面的代码无法运行。
（此规则只看表格本身，与实际起点无关，最后执行一次即可。）

## 输出格式

```markdown
| 章 | 名称 | 状态 | 预计学时 |
|----|------|------|----------|
| 1 | 初识智能体 | 跳过 | -- |
| 2 | 智能体发展史 | 跳过 | -- |
| 3 | 大语言模型基础 | 复习 | 4 |
| 4 | 智能体经典范式构建 | 学习 | 6 |
| ... | ... | ... | ... |
```

表格规则：

- 「跳过」的章节学时显示 `--`，不计入总时长
- 「复习」「学习」的章节显示完整学时并计入总时长
- 表格下方汇总一句：「你的个性化路径：约 X 小时，共 Y 章。」其中 Y =
  「复习」+「学习」的章节总数

最后给一段简短建议：从哪一章开始、根据最薄弱的区域先补什么，并提醒配套代码在
`code/chapterN/`，环境配置参考 `Extra-Chapter/Extra07-环境配置.md`。

## 规则

- 逐题提问，等用户答完一题再出下一题
- 全部答完之前不公布任何答案和解析
- 用户答「不知道」「跳过」记 0 分，照常继续
- 不要因为用户口头描述背景就修改分数——只认答题结果
- 最终建议里不要复述全部 10 题的解析，只挑答错的简要说明
