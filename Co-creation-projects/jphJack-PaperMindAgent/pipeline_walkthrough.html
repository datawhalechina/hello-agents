③ 向量索引构建 BGE-m3 → Chroma + BM25

处理流程

  1. 分块：按段落累积到 ~500 字符落块，每块携带 section 标题

  4. 同步构建 BM25：倒排索引供关键词检索

定位：RAG 是"点查询工具"而非"分析引擎"，仅在结构化摘要不够用时调用（步骤④⑤ 中需原文细节佐证时）。混合搜索 = Chroma 向量（α=0.6）+ BM25（α=0.4）分数归一化加权融合。

8Prompt 设计的 5 个核心原则

贯穿所有 prompt 的设计哲学。

① System 角色锚定

每个 prompt 都用 system 消息锁定角色（"你是 XX 专家"），并在末尾强调"只输出严格 JSON"，避免自由文本。

② 结构化输出强制

全部用 Function Calling 或显式 JSON Schema，避免 LLM 自由发挥导致解析失败。步骤② 用 tool_choice={"type":"function",...} 强制调用。

③ 防编造机制

source_sections 强制溯源 + "严禁臆造" + "缺失填暂无"。步骤② limitations 字段特别约束：论文未明确承认时填"论文未明确陈述局限"而非编造。

④ 上下文注入

把前序步骤的结构化产物作为"证据"喂给模型，而非让模型凭空推理。步骤④ 喂对比矩阵、步骤⑦ 喂 4 字段聚合。

⑤ 降级兜底

每个 LLM 调用都有 try/except，失败时回退到本地格式化或默认值。步骤⑦ LLM 失败 → _format_markdown() 本地组装。

9降级与容错策略

每个步骤都有失败兜底，局部失败不阻塞全局。

失败点降级路径影响
单篇论文解析失败隔离跳过，独立缓存可单独重跑不影响其他论文

论文超长截断按章节分块抽取后合并去重无影响
Controller 规划失败异常捕获 + 回退默认七步无影响
