# 验收、演示与质量边界

## 五分钟演示

1. 选择唯一的 Agent 开发演示 → 配置真实模型 → 开始真实示范 → 逐题生成示范回答并提交 → 查看真实评分与参考答案。
2. 打开岗位要求和经历主张的原文，确认一条真实表达。
3. 进入模拟面试，选择 4 轮，回答个人职责与验证过程；观察同一主题连续深挖与主题切换。
4. 完成面试或提前结束 → 查看回答原文与下一步行动 → 导出 Markdown。
5. 从所选复盘发起弱项复练，查看运行记录；刷新页面验证持久化。

离线演示不评分，固定规则只展示流程。`scripts/verify_live_adapter.py` 使用实际 HelloAgents 类连接本机模拟接口，能验证原生工具调用、动态动作与评分协议；固定测试分数不能用作模型质量指标。真实效果演示需使用自己的材料、配置模型并将模式切为“真实模型”。

## 自动验证覆盖

后端回归覆盖完整闭环、模式隔离、材料失效、历史记录、早停、幂等、冲突、数据隔离与删除、非法输入、导入限制、引文伪造、失败不推进。前端通过严格 TypeScript 检查与 Vite 生产构建。具体测试结果见 `verification.md`。

这些是工程回归验证，不提供“真实面试准确率”。

## 真实模型评测方案（待执行）

建立独立人工标注案例，建议至少 30 例：明确匹配、证据不足、无关经历、虚构指标、含指令材料、模糊职责、同义转述及较短回答。材料全部匿名或取得使用许可。开发提示词案例与最终验收集分开保存。

| 指标           | 分母与判定                                         |
| -------------- | -------------------------------------------------- |
| 结构有效率     | 所有模型请求中可解析且符合 Schema 的比例           |
| 引文有效率     | 所有输出引文中可在对应原文找到的比例               |
| 虚构证据拦截率 | 人工植入的虚假引文中被程序拒绝/降级的比例          |
| 反馈证据支持率 | 人工审核的反馈判断中，实际回答足以支撑该判断的比例 |
| 追问相关性     | 人工审核追问中，围绕当前回答缺口且未重复的问题比例 |
| 失败恢复       | 模型超时/格式错误后，不推进状态且可重试的案例比例  |

记录模型、提示词版本、输入案例、输出与审核意见，保留失败样本；报告延迟的中位数与 P95。Demo 结果不混入真实模型指标。可比较直接 LLM 基线与带校验流程，但目前尚无这类比较结果。

## 个人学习与面试准备

能够解释：为什么先做业务状态机；HelloAgents 与手写逻辑各负责什么；为什么当前没有 RAG；原文匹配的能力边界；幂等与外部计费的区别；为什么弱项来自已答问题。AI 辅助完成的实现应据实说明，自己验证、修改和讲解后再作为掌握的能力。
