# 验证方式与边界

以 [README](../README.md) 的安装和启停步骤为唯一操作入口；测试与检查由 `scripts/check.py` 汇总执行。以下使用虚构材料。自动协议测试不需要外部模型密钥；真实示范验收使用本机配置，密钥不写入测试产物或仓库。

## 自动验证

| 检查       | 覆盖                                                                                                                                                       |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 后端回归   | 单一演示幂等与并发、旧演示迁移、真实示范草稿缓存与个人代答隔离、工作区隔离、材料失效、多轮追问、主题切换、预算、幂等、冲突、引用验证、评分失败恢复与旧记录 |
| 模型适配   | 实际 HelloAgents 类连接本机模拟服务，验证原生工具往返、独立评分、逐题参考答案和 Token 汇总                                                                 |
| 配置与用量 | `.env` 原子写入、失败恢复、密钥不回显、Origin 检查、一次格式修正、推理耗尽预算的截断诊断、缺失 usage                                                       |
| 启停控制   | 实例令牌、拒绝无令牌或带浏览器 Origin 的停止请求、拒绝重复启动、退出时清理自身状态                                                                         |
| 前端       | TypeScript 严格检查、Prettier、Vite 生产构建                                                                                                               |
| Notebook   | 虚构材料调用生产 API 完成离线闭环，提交文件不保留执行输出                                                                                                  |

| Linux（WSL Ubuntu）/ Python 3.12 / Node.js 24 | 干净环境安装、离线演示、49 项测试、全部格式与构建检查、HelloAgents 协议验证、POSIX shell 启停和重复停止通过 |

## 结果解释

本机模拟服务返回固定评分，只能证明协议、状态、引用核验和加权计算符合预期。没有据此宣称真实面试准确率、追问信息增益、模型评分与人工一致性或用户效果提升。真实评测方案见 [acceptance.md](acceptance.md)。本地测试通过不代表远端 CI 已通过或 PR 已合并。

## 真实模型 Good / Bad case 自测

使用同一份虚构 Agent 开发材料，分别进行四轮具体且有依据的回答与含糊、错误、承认未参与的回答；标签不传入独立评审。覆盖材料分析、动态追问与切换、回答幂等、独立评分、逐题参考答案、导出和弱项复练启动。

自测发现并修复评审混用问题 ID 与回答 ID、长评审读超时及 SDK 隐式重发；新增回归后两平台各 49 项通过。真实模型的用量与评分结果在本次独立验收记录中提供，测试数据库和模型输出不提交仓库。

Good case 的长回答在 12000 输出预算下曾截断，需要在隔离进程使用更高的测试预算验证。不会据此将所有服务商的默认预算一律调高，也未改写用户的 .env。两个合成案例只能验证该流程与明显优劣区分，不构成评分一致性或准确率评测。

浏览器验收检查侧栏操作顺序、取消独立证据菜单、同页准备建议、真实模型示范作答与独立复盘。原始测试数据库与运行日志不提交；README 仅展示经过隐私检查的虚构材料案例截图，并标明真实模型历史回放。测试模型输出预算仅在隔离进程设置为 24000，用户 .env 不变；实际分数和耗时不作为稳定预设值。

## 演示自动作答回归

## 模型消耗记录精简

运行记录与顶部汇总使用同一模型筛选口径：保留正 Token、已发起但用量未知或不完整的调用，排除工具、离线规则、未发请求的检查及已确认零用量。筛选在最近 100 条限制之前完成，历史工具轨迹不删除。新增覆盖噪声超过 100 条、旧记录兼容及未知用量的回归；Windows、Linux 各 57 项通过，浏览器验证汇总、刷新和桌面/手机布局通过。

## 流式示范回答验收

Windows、Linux 当前各 64 项回归通过，新增 7 项覆盖增量帧、最终累计用量、按题缓存、截断、断流、缺失终止标志、空正文、缺失用量、取消关闭与未完成草稿不保存。实际 HelloAgents 客户端连接本机 SSE 协议服务，浏览器确认先收到局部文字、done 前禁用提交、重入复用缓存、断流后显式重试及上一题回答进入下一次工具上下文；桌面和手机无横向溢出。

另使用已配置真实服务验证一题原生面试和示范正文流式生成，浏览器在结束前已看到正文，最终 972 字符的草稿保存成功，服务返回 2567 Token 且用量完整。该次只验证生成和保存，没有提交回答或重新评定面试分数；输出预算仅在隔离验收进程设置为 24000，没有改写用户 .env。
