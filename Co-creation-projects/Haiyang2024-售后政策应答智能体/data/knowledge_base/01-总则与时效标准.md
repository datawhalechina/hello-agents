# 总则与时效标准

> 业务域：通用规定 ｜ 规则前缀：`GEN` ｜ 责任部门：客户服务中心
> 本文件是全部售后规则的**总纲**，其他各文件的判定与处理均以本文件为准。

---

## GEN-001 适用范围与术语定义

| 规则编号 | GEN-001 |
| 适用场景 | 全部售后咨询 |
| 责任部门 | 客户服务中心 |
| 关联规则 | 全部 |

### 适用范围

本政策适用于平台自营及平台内商家在售商品的售后咨询与处理，覆盖以下六类诉求：

| 类别 | 说明 | 对应规则族 |
|---|---|---|
| 物流履约 | 发货、配送、签收、退回 | `LOG` |
| 支付退款 | 支付异常、退款进度、金额差异 | `PAY` |
| 退换货 | 无理由退货、质量问题、少件漏发、维修 | `RET` |
| 价格与凭证 | 价格保护、优惠退回、发票 | `PRC` / `INV` |
| 特殊品类 | 生鲜、数码、定制、虚拟商品 | `SPC` |
| 投诉与赔偿 | 投诉升级、金额争议、平台介入 | `CMP` |

### 术语定义

| 术语 | 定义 |
|---|---|
| **签收日** | 物流系统记录的签收时间，为用户主张权利的起算点 |
| **自然日** | 含周末与法定节假日的日历日；**售后时效统一按自然日计算** |
| **工作日** | 不含周末与法定节假日；**资金类时效按工作日计算** |
| **二次销售** | 商品未经使用、包装完好、配件齐全、不影响再次出售的状态 |
| **三包** | 修理、更换、退货三项责任，依据《部分商品修理更换退货责任规定》 |
| **原路退回** | 退款按原支付路径返还至付款账户 |
| **预授权** | 支付渠道在交易确认前冻结的资金，未实际扣款 |
| **时效标准** | 本政策规定的处理时限，**均为参考值，以实际处理为准** |

### 法规依据

本政策的编写参照以下法规的相关规定：

- 《中华人民共和国消费者权益保护法》
- 《中华人民共和国电子商务法》
- 《中华人民共和国产品质量法》
- 《网络交易监督管理办法》
- 《快递暂行条例》
- 《部分商品修理更换退货责任规定》

> **重要提示**：具体法律适用需结合个案情况，客服与智能体**不得自行作出法律判断**，涉及法律责任认定的应转法务或人工处理。

## GEN-002 售后服务基本原则

| 规则编号 | GEN-002 |
| 适用场景 | 全部售后处理 |
| 责任部门 | 客户服务中心 |
| 关联规则 | GEN-001、TAL-001、LIM-001 |

### 五项基本原则

| 原则 | 含义 | 违反后果 |
|---|---|---|
| **依法合规** | 不得设置低于法定标准的条件，不得以格式条款排除用户法定权利 | 条款无效、监管处罚 |
| **证据优先** | 涉及质量、少件、破损的，以证据材料为判定基础 | 误判、赔付损失 |
| **不越权承诺** | 涉及金额、审核结论、时效的，不得超出权限承诺 | 真实赔付成本 |
| **信息最小化** | 仅收集处理该诉求所必需的信息，不索取无关个人信息 | 违反个人信息保护要求 |
| **全程留痕** | 处理过程、依据、结论须可追溯 | 争议时无法举证 |

### 处理优先级

当用户同时涉及多个诉求时，按以下优先级处理：

```
人身安全类 > 资金安全类 > 时效紧迫类 > 一般咨询类
```

**示例**：用户同时反馈"商品漏电"和"想退货"，应优先处理人身安全问题，立即提示停止使用并联系售后，而非直接走退货流程。

## GEN-003 时效标准总表

| 规则编号 | GEN-003 |
| 适用场景 | 需要向用户说明时效时 |
| 责任部门 | 客户服务中心 |
| 关联规则 | TAL-003 |

### 处理时效

| 环节 | 时效标准 | 计算方式 |
|---|---|---|
| 首次响应 | 30 分钟内 | 工作时间 |
| 一般咨询处理 | 24 小时内 | 自然日 |
| 质量问题审核 | 1–2 个工作日 | 工作日 |
| 退换货申请审核 | 1–3 个工作日 | 工作日 |
| 投诉受理确认 | 2 小时内 | 工作时间 |
| 投诉处理反馈 | 3 个工作日 | 工作日 |

### 履约时效

| 环节 | 时效标准 | 计算方式 |
|---|---|---|
| 订单发货 | 48 小时内（预售等特殊商品以商品页说明为准） | 自付款成功起 |
| 物流揽收 | 发货后 24 小时内 | 自然日 |
| 物流在途 | 一般 1–5 自然日（偏远地区顺延） | 自揽收起 |
| 物流信息更新间隔 | 正常不超过 72 小时 | — |

### 资金时效

| 环节 | 时效标准 | 计算方式 |
|---|---|---|
| 退款审核 | 1–3 个工作日 | 工作日 |
| 退款到账（微信 / 支付宝） | 1–3 个工作日 | 工作日 |
| 退款到账（储蓄卡） | 3–7 个工作日 | 工作日 |
| 退款到账（信用卡） | 3–15 个工作日 | 工作日 |
| 预授权解冻 | 1–3 个工作日 | 工作日 |

> **统一表述要求**：所有时效对外说明时，**必须附加**"以实际处理时间为准"，不得作为承诺。详见 [TAL-003 时效表述规范](08-客服话术规范.md#tal-003-时效表述规范)。

## GEN-004 责任分工与升级机制

| 规则编号 | GEN-004 |
| 适用场景 | 判断由谁处理、何时升级 |
| 责任部门 | 客户服务中心 |
| 关联规则 | CMP-001、CMP-002 |

### 责任分工

| 环节 | 责任部门 | 权限边界 |
|---|---|---|
| 咨询应答、信息收集 | 客服 / 智能体 | 不得承诺 |
| 退货换货审核 | 售后服务中心 | 单笔 ≤ 500 元 |
| 退款审核 | 财务结算部 | 单笔 ≤ 2000 元 |
| 超权限退款 | 财务经理审批 | 2000 元以上 |
| 赔偿处理 | 客户服务中心 + 合规 | 一律人工审批 |
| 法律责任认定 | 合规与法务部 | 一律人工处理 |
| 平台介入、监管投诉 | 合规与法务部 | 一律人工处理 |

### 升级触发条件

出现以下任一情况，**必须**转人工并升级至对应部门：

| 触发条件 | 升级目标 |
|---|---|
| 涉及赔偿金额诉求 | 客户服务中心（人工） |
| 涉及法律责任认定 | 合规与法务部 |
| 要求平台介入或监管投诉 | 合规与法务部 |
| 情绪激烈且要求明确责任归属 | 客户服务中心（人工） |
| 多轮追问后仍信息不完整 | 客户服务中心（人工） |
| 意图无法归类 | 客户服务中心（人工） |
| 涉及人身安全 | 立即升级 + 提示停止使用 |
| 单笔金额超出权限 | 对应审批层级 |

### 升级处理要求

1. **先响应，再转交**：不得以"需要转人工"直接结束对话，须先给出用户明确的后续动作
2. **信息完整移交**：转交时须附带已收集的结构化信息与问题摘要
3. **告知材料清单**：明确告知用户需准备的材料，减少重复沟通
4. **时效承诺**：转交后告知用户大致响应时间（按 GEN-003 的投诉受理时效）
