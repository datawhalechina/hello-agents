# 电商售后服务政策知识库

> 本目录为**售后客服智能体**的政策依据库，用于支撑政策检索、处理策略生成与风险约束。
>
> 内容按**正规电商平台售后政策体系**编写，覆盖物流履约、支付退款、退换货三包、价保发票、特殊品类、投诉赔偿六个业务域。

## 三、文档结构约定

### 3.1 每条规则的固定结构

```markdown
## {规则编号} {规则名称}

| 规则编号 | LOG-001 |
| 适用场景 | ... |
| 责任部门 | ... |
| 时效标准 | ... |
| 关联规则 | ... |

### 判定标准
### 处理流程
### 客户沟通要点
### 禁止承诺
### 需补充信息
```

### 3.2 为什么统一用 `## ` 分节

`##` 是切分的最小语义单元：检索层按 `#` / `##` 两级切分（**不切 `###`**），保证**一条规则一个完整切片**，内部的 `###` 子节（含「禁止承诺」）不被打散。

这样设计是为了规避按固定长度切分的典型问题：命中条件却丢了结论、命中表格却丢了表头。

### 3.3 强制字段说明

| 字段 | 作用 |
|---|---|
| `规则编号` | 检索命中标识、评测断言标识 |
| `时效标准` | 数值化的时效承诺边界（避免笼统表述） |
| **`禁止承诺`** | **合规红线**，直接对应评测中的 `must_not_contain` 断言 |
| `需补充信息` | 触发追问的依据，对应缺参校验节点 |
| `关联规则` | 支撑跨规则推理（如物流超时同时涉及 LOG-001 与 PAY-001） |

## 四、合规声明

> **本目录内容为技术验证用的模拟数据，非任何真实平台的政策文件，引用法律条文仅为示意，不构成法律意见。**

编写时遵循以下原则：

| 原则 | 说明 |
|---|---|
| **不越权** | 所有涉及金额、赔偿、审核结论的表述，均指向审批环节，不给出承诺 |
| **不编造** | 时效均标注"以实际处理为准"；不确定的状态明确标注"需核实" |
| **依据可溯** | 涉及法定权利的规则（如七天无理由、三包）标注法规依据 |
| **责任明确** | 每条规则标注责任部门，避免职责模糊 |
| **用户优先** | 时效标准取行业惯例中的合理值，不刻意压缩用户权益 |

## 五、维护规范

| 场景 | 动作 |
|---|---|
| 政策调整 | 保留旧版本，新增版本并标注生效日期，用于验证"命中旧制度"的排查场景 |
| 新增规则 | 按所属业务域追加编号（如新增物流规则依次为 LOG-006） |
| 修改规则编号 | **禁止**。编号是评测断言的锚点，改动需同步更新评测集 |
| 新增业务域 | 在第二节的编号体系中登记前缀与责任部门 |

| 关联 | 说明 |
