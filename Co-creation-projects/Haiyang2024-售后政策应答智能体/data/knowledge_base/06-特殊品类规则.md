# 特殊品类规则

> 业务域：特殊品类 ｜ 规则前缀：`SPC` ｜ 责任部门：品类运营部
> 覆盖场景：生鲜食品、数码激活、定制商品、虚拟商品
> 说明：本文件规则**优先于** `RET` 通用规则适用；本文件未规定的，回退至通用规则

---

## SPC-001 生鲜食品类

| 规则编号 | SPC-001 |
| 适用场景 | 生鲜、冷藏冷冻、短保食品的售后 |
| 责任部门 | 品类运营部 + 售后服务中心 |
| 时效标准 | **签收后 24 小时内**反馈；审核 1 个工作日 |
| 依据 | 《消费者权益保护法》第二十五条（鲜活易腐商品不适用无理由退货） |
| 关联规则 | RET-002、RET-006 |

### 判定标准

| 情形 | 判定 |
|---|---|
| 变质、腐烂、异味 | 需照片 / 视频证明，且在签收后 24 小时内反馈 |
| 少件、错发 | 需包裹面单与实物照片 |
| 与描述不符（规格、重量） | 需称重照片或对比照片 |
| "不新鲜""不好吃"（主观） | **不属质量问题**，无法按质量退换 |
| 超过 24 小时才反馈 | 难以判定责任，转人工判定 |

### 处理流程

1. **优先确认反馈时间**（是否在 24 小时内）
2. 引导提供证据：实物照片 / 视频、称重照片、包裹面单
3. 材料齐备后提交审核
4. 确认为品质问题的：退款或补发，无需寄回（生鲜一般不退回）
5. 超出时效或证据不足的：说明原因，转人工判定

### 客户沟通要点

- 首句致歉，表达对食品安全的重视
- 明确说明 24 小时反馈时限的**原因**（生鲜品质随时间变化难以判定）
- 涉及食品安全疑虑的（如变质、异味），**立即提示停止食用**

### 禁止承诺

- ❌ 不可承诺"一定是我们的问题"
- ❌ 不可承诺赔偿金额
- ❌ 不可承诺"不用寄回就一定退款"（需先审核）
- ❌ 不可对超过 24 小时的诉求直接拒绝，应转人工

### 需补充信息

订单号、签收时间、实物照片或视频、问题描述、是否已食用。

## SPC-002 数码产品与激活规则

| 规则编号 | SPC-002 |
| 适用场景 | 手机、电脑、平板、智能设备等的售后 |
| 责任部门 | 品类运营部 + 售后服务中心 |
| 时效标准 | 同 RET-002；激活类争议审核 1–2 个工作日 |
| 关联规则 | RET-002、RET-004、RET-006 |

### 判定标准

| 情形 | 是否适用无理由退货 | 说明 |
|---|---|---|
| 未拆封 | ✅ 适用 | 包装完整 |
| 已拆封但未激活、未使用 | ✅ 通常适用 | 需配件齐全、无使用痕迹 |
| **已激活**（联网激活、登录账号） | ❌ 不适用无理由退货 | 激活信息不可逆，影响二次销售 |
| 已贴膜 / 已装软件 | ⚠️ 视情况 | 可能影响二次销售判定 |
| 出现性能故障 | 按 RET-004 三包处理 | 与是否激活无关 |

### 处理流程

1. 确认商品状态与是否激活
2. 无理由退货诉求：
   - 未激活：按 RET-001 流程
   - 已激活：说明不适用原因，并说明质量问题仍按 RET-004 处理
3. 质量诉求：引导提供故障证据，转质检
4. 涉及账号解绑的：提示用户处理账号与数据（见下方注意）

### 重要提示：数据与账号

| 项 | 要求 |
|---|---|
| 退货前 | 提示用户**自行备份数据并退出账号**，平台不承担数据丢失责任 |
| 隐私 | 不得引导用户提供账号密码 |
| 检测 | 维修 / 退换需检测时，提示用户提前处理个人数据 |

### 禁止承诺

- ❌ 不可承诺"激活了也能退"
- ❌ 不可承诺"数据一定不会丢"
- ❌ 不可承诺检测结果与检测周期
- ❌ 不可承诺一定免费维修

### 需补充信息

订单号、商品是否激活、购买时间、故障描述、是否已备份数据。

## SPC-003 定制类商品

| 规则编号 | SPC-003 |
| 适用场景 | 刻字、定制尺寸、定制图案等按需定作商品 |
| 责任部门 | 品类运营部 + 售后服务中心 |
| 时效标准 | 同 RET-002 |
| 依据 | 《消费者权益保护法》第二十五条（消费者定作的商品不适用无理由退货） |
| 关联规则 | RET-002、RET-006 |

### 判定标准

| 情形 | 是否适用无理由退货 |
|---|---|
| 定制商品，已完成制作 | ❌ 不适用 |
| 定制商品，尚未开始制作 | ⚠️ 可协商取消，视商家规则 |
| 定制商品存在制作错误（与用户确认稿不符） | ✅ 属商家责任，可重做或退款 |
| 定制商品存在质量问题 | ✅ 按 RET-002 处理 |
| 非定制类商品 | 回退至 RET-001 |

### 处理流程

1. 确认商品是否属定制类
2. 无理由退货诉求：说明不适用原因与依据
3. **制作错误诉求**：
   - 引导提供确认稿与实际成品的对比
   - 确认属商家责任的，提供重做或退款方案
4. **质量问题诉求**：按 RET-002 流程处理

### 客户沟通要点

- 说明"定作商品不适用无理由退货"的法定依据
- 强调**制作错误与质量问题仍可处理**，避免用户误解为"定制就不管了"
- 下单前确认稿的重要性需在沟通中体现

### 禁止承诺

- ❌ 不可承诺定制商品可无理由退货
- ❌ 不可承诺重做的完成时间
- ❌ 不可在未对比确认稿前判定责任归属

### 需补充信息

订单号、定制内容、确认稿、实际成品照片、问题描述。

## SPC-004 虚拟商品与充值类

| 规则编号 | SPC-004 |
| 适用场景 | 会员充值、游戏点卡、电子券、课程、软件授权等 |
| 责任部门 | 品类运营部 + 财务结算部 |
| 时效标准 | 未使用类争议 1–3 个工作日 |
| 依据 | 《消费者权益保护法》第二十五条（在线下载或已拆封的数字化商品不适用无理由退货） |
| 关联规则 | PAY-002、RET-006 |

### 判定标准

| 情形 | 处理方式 |
|---|---|
| 未发货 / 未充值，用户要求退款 | ✅ 可退款 |
| 已充值到账但用户误操作 | ❌ 通常不可退（已消耗） |
| 充值未到账 | 核实后补发或退款 |
| 重复充值 | 按 PAY-002 处理 |
| 卡券已使用 | ❌ 不可退 |
| 卡券未使用但在有效期内 | 视平台规则，部分支持退 |
| 商品下架 / 商家跑路 | 转人工，按平台保障规则处理 |

### 处理流程

1. 核对充值 / 交付状态（是否已到账、是否已使用）
2. **未到账**：核实后补发或退款
3. **已使用**：说明不适用无理由退货的原因
4. **误操作类**：说明规则，涉及金额较大的转人工
5. 涉及第三方平台充值的，说明需协调第三方核实

### 客户沟通要点

- 说明虚拟商品的特殊性（交付即消耗、不可逆）
- 未到账类问题优先处理，给出明确时效
- 误操作类问题表达理解，但需说明规则

### 禁止承诺

- ❌ 不可承诺"已充值的也能退"
- ❌ 不可承诺一定追回已消耗的权益
- ❌ 不可承诺第三方平台的退款结果
- ❌ 不可引导用户提供账号密码协助操作

### 需补充信息

订单号、充值账号（仅需脱敏信息，不索取密码）、充值时间、是否到账、是否已使用。
