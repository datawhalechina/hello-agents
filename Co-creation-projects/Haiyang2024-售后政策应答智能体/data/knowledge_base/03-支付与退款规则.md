# 支付与退款规则

> 业务域：支付与退款 ｜ 规则前缀：`PAY` ｜ 责任部门：财务结算部
> 覆盖场景：退款时效、重复扣款、部分退款、退款失败
> 通用要求：本域所有对外表述**必须**注明"以支付渠道实际处理为准"

---

## PAY-001 退款时效与渠道规则

| 规则编号 | PAY-001 |
| 适用场景 | 用户申请退款后咨询进度、询问到账时间 |
| 责任部门 | 财务结算部 |
| 时效标准 | 退款审核 1–3 个工作日；到账时效按渠道区分 |
| 关联规则 | GEN-003、LOG-004、RET-001 |

### 判定标准

退款需经过**四个环节**，任一环节未完成都会影响到账时间：

| 环节 | 责任方 | 参考时效 |
|---|---|---|
| ① 退款审核 | 平台 | 1–3 个工作日 |
| ② 原路退回发起 | 平台 | 审核通过后即时发起 |
| ③ 支付渠道处理 | 支付渠道 | 1–3 个工作日 |
| ④ 银行入账 | 银行 | 视卡种而定 |

### 到账时效参考

| 支付方式 | 参考到账时间 | 计算方式 |
|---|---|---|
| 微信支付 / 支付宝 | 1–3 个工作日 | 工作日 |
| 储蓄卡 | 3–7 个工作日 | 工作日 |
| 信用卡 | 3–15 个工作日 | 工作日（视账单周期） |
| 余额 / 平台钱包 | 即时到账 | — |

### 处理流程

1. 核对退款申请状态（是否已审核通过、是否已发起原路退回）
2. 说明四环节流程与当前所处环节
3. 处于参考时效内的：说明属正常处理周期，建议稍作等待
4. 超出参考时效仍未到账：
   - 协助发起支付渠道查询
   - 请用户提供支付渠道的退款记录截图
   - 记录并跟进
5. 退款状态异常的，转人工核查

### 客户沟通要点

| 要点 | 说明 |
|---|---|
| 先安抚 | 涉及资金，用户敏感度高 |
| 讲清环节 | 让用户理解并非平台单方面可控 |
| 给区间不给点 | 只给时效区间，不给具体日期 |
| 给下一步 | 明确说明"如果超过 X 天我们再帮您查" |

### 禁止承诺

- ❌ **不可承诺"明天到账""马上到账"**
- ❌ 不可承诺具体到账日期
- ❌ 不可编造退款状态或银行处理结果
- ❌ 不可替支付渠道或银行作出结论
- ❌ 不可承诺"一定能退回来"

### 需补充信息

订单号、支付方式、退款申请时间、支付渠道退款记录截图。

## PAY-002 重复扣款与支付异常

| 规则编号 | PAY-002 |
| 适用场景 | 同一订单被多次扣款、支付失败但资金被扣 |
| 责任部门 | 财务结算部 |
| 时效标准 | 核实 1–3 个工作日；确认后按原路退回 |
| 关联规则 | PAY-001、PAY-004、CMP-002 |

### 判定标准

| 情形 | 常见原因 | 处理方向 |
|---|---|---|
| 同订单两次实际扣款 | 系统重复下单或支付渠道重复请求 | 确认为重复支付 → 原路退回 |
| 支付失败但资金被扣 | 多为**预授权冻结**，非实际扣款 | 通常 1–3 个工作日自动解冻 |
| 一次扣款但订单未生成 | 订单创建失败 | 核查订单状态后处理 |
| 多笔相近金额扣款 | 可能为多笔订单 | 需逐笔核对 |

### 处理流程

1. 请用户提供扣款记录（支付渠道账单中的流水号、时间、金额）
2. 核对订单的实际支付状态与订单数量
3. 判定性质：

| 判定结果 | 处理方式 |
|---|---|
| 确认重复扣款 | 发起原路退回，按 PAY-001 计时 |
| 确认预授权冻结 | 说明冻结机制，告知自动解冻时效 |
| 确认为多笔独立订单 | 说明扣款构成，协助确认是否需取消部分订单 |
| 无法判定 | 记录并转人工核查 |

4. 告知用户后续跟进方式

### 禁止承诺

- ❌ 不可承诺"今天就退回来"
- ❌ 未核实前不可确认"确实是重复扣款"
- ❌ 不可承诺冻结款项的准确解冻时间
- ❌ 不可承诺赔偿或补偿

### 需补充信息

订单号、各笔扣款的流水号、扣款时间、金额、支付渠道。

## PAY-003 部分退款与差额处理

| 规则编号 | PAY-003 |
| 适用场景 | 订单部分商品退款、金额差异、优惠分摊后的退款 |
| 责任部门 | 财务结算部 |
| 时效标准 | 同 PAY-001 |
| 关联规则 | PAY-001、RET-003、PRC-002 |

### 判定标准

部分退款的金额需扣除**优惠分摊**部分：

| 情形 | 退款金额计算 |
|---|---|
| 订单使用满减优惠，仅退部分商品 | 按商品实付金额退款，优惠按比例分摊扣除 |
| 订单使用优惠券，全部退货 | 退款金额为实付金额；优惠券按规则退回或作废 |
| 订单包含赠品，退主商品 | 赠品需一并退回，否则按赠品价值扣除 |
| 多件商品退其中一件 | 按该商品实付金额退款 |

### 处理流程

1. 明确退款范围（整单 / 部分商品）
2. 说明金额构成：商品金额 − 优惠分摊 + 运费（按 LOG-005 判定）
3. 用户对金额有异议的：
   - 提供实付明细
   - 说明优惠分摊规则
   - 仍有异议的转人工复核
4. 确认后发起退款

### 禁止承诺

- ❌ 不可承诺"按原价全额退"
- ❌ 不可承诺优惠券一定返还
- ❌ 不可在核算完成前给出具体退款金额

### 需补充信息

订单号、退款商品清单、实付金额、使用的优惠类型。

## PAY-004 退款失败与退回处理

| 规则编号 | PAY-004 |
| 适用场景 | 退款发起后失败、退款被退回 |
| 责任部门 | 财务结算部 |
| 时效标准 | 失败后 1–3 个工作日重新发起 |
| 关联规则 | PAY-001、PAY-002 |

### 常见失败原因

| 原因 | 说明 | 处理方式 |
|---|---|---|
| 原支付账户已注销 | 无法原路退回 | 需用户提供新的收款账户并完成身份核验 |
| 银行卡已挂失 / 换卡 | 原卡号失效 | 同上 |
| 支付渠道订单超期 | 超过渠道退款有效期 | 转为人工转账处理 |
| 账户状态异常 | 被冻结、限制收款 | 需用户先解决账户问题 |
| 系统处理异常 | 平台侧失败 | 重新发起 |

### 处理流程

1. 查明失败原因
2. 属用户账户原因的：说明需用户配合的事项
3. 属平台原因的：重新发起并告知时效
4. 无法原路退回的：
   - 告知需提供替代收款方式
   - 说明需完成**身份核验**（合规要求，不可省略）
   - 转人工处理，**智能体不得自行收集账户信息**

### 客户沟通要点

- 说明失败原因，避免用户误以为平台故意拖延
- 需用户操作的部分，给出明确指引
- 涉及账户信息时，引导用户通过**官方安全渠道**提交

### 禁止承诺

- ❌ 不可承诺"换个账户马上就能退"
- ❌ 不可在对话中索取完整的银行卡号、身份证号等敏感信息
- ❌ 不可承诺补偿因退款失败造成的损失

### 需补充信息

订单号、退款失败提示信息、原支付方式。
