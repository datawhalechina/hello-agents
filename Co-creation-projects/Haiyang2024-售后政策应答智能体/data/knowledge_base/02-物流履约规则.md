# 物流履约规则

> 业务域：物流履约 ｜ 规则前缀：`LOG` ｜ 责任部门：仓储物流部
> 覆盖场景：发货时效、物流停滞、签收异常、拒收退回、运费承担

---

## LOG-001 发货时效与超时处理

| 规则编号 | LOG-001 |
| 适用场景 | 用户催发货、订单超过承诺时效未发出 |
| 责任部门 | 仓储物流部 |
| 时效标准 | 付款成功后 48 小时内安排发货（特殊商品以商品页说明为准） |
| 关联规则 | GEN-003、PAY-001、LOG-005 |

### 判定标准

| 条件 | 判定 |
|---|---|
| 订单状态为"待发货"或"已付款未出库" | 进入本规则 |
| 距付款成功未超 48 小时 | 属正常范围，告知预计时间 |
| 距付款成功已超 48 小时 | **判定为发货超时**，进入加急流程 |
| 商品页标注了预售、定制等特殊发货期 | 以商品页说明为准，不适用 48 小时标准 |

### 处理流程

1. 核对订单状态与实际付款时间
2. 查询仓库发货排期与库存状态
3. **未超时**：告知预计发货时间，说明出库流程
4. **已超时**：
   - 升级为加急催发并记录超时原因
   - 同步用户处理进度
   - 依平台规则评估是否触发超时赔付（超时赔付属赔偿范畴，需人工审批，见 CMP-002）
5. 用户明确要求取消并退款：转 [PAY-001](03-支付与退款规则.md#pay-001-退款时效与渠道规则) 处理

### 客户沟通要点

| 要点 | 说明 |
|---|---|
| 先致歉 | 首句对等待表达歉意 |
| 说明依据 | 明确告知所依据的时效标准 |
| 给出动作 | 说明已采取的具体动作（催发 / 核实） |
| 不承诺时点 | 只给区间，不给具体时间点 |

### 禁止承诺

- ❌ 不可承诺**具体发货时间点**（如"明天上午 10 点前一定发出"）
- ❌ 不可承诺快递公司**当天揽收**
- ❌ 不可承诺"今天一定能发"
- ❌ 不可承诺超时赔付的具体金额

### 需补充信息

| 信息 | 必要性 |
|---|---|
| 订单号 | 必需（未提供时须追问） |
| 收货地址 | 加急发货时可能需要确认 |
| 是否接受改期发货 | 用于给出处理选项 |

## LOG-002 物流停滞与丢件处理

| 规则编号 | LOG-002 |
| 适用场景 | 物流信息长时间未更新、快件疑似丢失 |
| 责任部门 | 仓储物流部 |
| 时效标准 | 查询工单 24 小时内提交；快递方核实 24–48 小时反馈 |
| 关联规则 | GEN-003、LOG-003、CMP-002 |

### 判定标准

| 条件 | 判定 |
|---|---|
| 物流信息更新间隔超过 72 小时 | 判定为**物流停滞** |
| 物流停滞超过 7 个自然日 | 可**申请介入核查** |
| 快递方书面确认丢件 | 判定为**丢件**，进入赔付流程 |
| 用户主观判断丢件但无快递方确认 | **不得判定为丢件** |

### 处理流程

1. 查询最新物流轨迹，确认停滞节点与时长
2. 向用户说明物流更新延迟的可能原因（中转、分拨、异常天气等）
3. 发起物流查询工单，催促快递方核实
4. 告知跟进方式与反馈时限
5. 快递方确认丢件的：
   - 联系用户确认补发或退款意愿
   - 补发按 [LOG-001](02-物流履约规则.md#log-001-发货时效与超时处理) 重新计算时效
   - 退款转 [PAY-001](03-支付与退款规则.md#pay-001-退款时效与渠道规则)

### 客户沟通要点

- 说明"物流更新延迟属常见情况"，避免用户过度焦虑
- 明确已发起查件动作，给出反馈时间
- 涉及高价值商品时，主动说明保障措施

### 禁止承诺

- ❌ 不可直接断言"包裹已丢失""肯定丢件了"
- ❌ 不可承诺具体送达日期
- ❌ 不可承诺快递方一定赔付
- ❌ 不可承诺赔付金额

### 需补充信息

订单号或物流单号、问题发生时间、是否已联系过快递方。

## LOG-003 签收异常与代收处理

| 规则编号 | LOG-003 |
| 适用场景 | 物流显示已签收但用户未收到、代收点代签、他人代收 |
| 责任部门 | 仓储物流部 |
| 时效标准 | 核实申请 24 小时内提交；核实周期 1–3 个工作日 |
| 关联规则 | LOG-002、CMP-002 |

### 判定标准

| 条件 | 判定 |
|---|---|
| 物流状态为"已签收"且用户主张未收到 | 进入本规则 |
| 签收人为用户本人或经其授权 | 属正常签收 |
| 签收人为代收点、门卫、他人 | 需用户确认是否为授权代收 |
| 用户确认从未授权代收且未收到 | 发起快递方核实流程 |

### 处理流程

1. 提供完整签收信息（签收时间、签收人、签收地点、签收方式）
2. 引导用户确认是否为家人、同事、门卫或代收点代收
3. 用户确认未收到：
   - 发起快递方核实，要求提供签收凭证
   - 告知核实周期与跟进方式
4. 核实结果为误领、错投的：协调追回或按丢件流程处理
5. 核实期间**不擅自承诺补发或赔付**

### 禁止承诺

- ❌ 核实完成前不可承诺补发、赔偿
- ❌ 不可断言包裹一定被误领或错投
- ❌ 不可承诺核实结果的出具时间

### 需补充信息

订单号、物流单号、签收时间、用户当时是否在场、是否询问过家人或代收点。

## LOG-004 拒收与退回处理

| 规则编号 | LOG-004 |
| 适用场景 | 用户拒收快件、包裹被退回 |
| 责任部门 | 仓储物流部 |
| 时效标准 | 退回入库后 1–3 个工作日完成验收与退款发起 |
| 关联规则 | PAY-001、RET-001、LOG-005 |

### 判定标准

| 条件 | 判定 |
|---|---|
| 用户在派送时明确拒收 | 进入退回流程 |
| 因用户原因（地址错误、长期未取）导致退回 | 运费由用户承担 |
| 因商品或物流原因导致退回 | 运费由平台承担 |
| 拒收后用户仍希望收货 | 视快件状态协调重新派送或重新下单 |

### 处理流程

1. 确认拒收原因与责任归属
2. 告知退回流程与预计入库时间
3. 快件退回入库后完成验收
4. 验收无误后发起退款，按 [PAY-001](03-支付与退款规则.md#pay-001-退款时效与渠道规则) 计算时效
5. 验收发现商品损坏的，需与用户确认责任

### 禁止承诺

- ❌ 不可承诺退款的具体到账日期
- ❌ 不可在验收完成前承诺全额退款

### 需补充信息

订单号、拒收原因、拒收时间。

## LOG-005 运费承担规则

| 规则编号 | LOG-005 |
| 适用场景 | 涉及退换货、拒收、补发时的运费归属判断 |
| 责任部门 | 仓储物流部 + 财务结算部 |
| 时效标准 | 运费争议 1–3 个工作日确认 |
| 关联规则 | RET-001、RET-002、LOG-004 |

### 判定标准

| 情形 | 运费承担方 |
|---|---|
| 商品质量问题导致的退换 | **平台承担** |
| 少件、漏发导致的补发 | **平台承担** |
| 物流原因导致的退回 | **平台承担** |
| 七天无理由退货（非质量问题） | **用户承担**（另有约定的除外） |
| 用户原因导致的拒收（地址错误、拒收非质量原因） | **用户承担** |
| 尺码不合适、不喜欢等个人原因换货 | 按平台公示规则，通常**用户承担** |
| 平台错发、漏发 | **平台承担** |

### 处理流程

1. 先判定问题性质（质量 / 非质量）
2. 明确运费承担方，并说明依据
3. 平台承担的：说明退运费流程与时效
4. 用户承担的：说明金额构成（如已购运费险则按保险规则处理）
5. 存在争议的：记录并转人工确认

### 禁止承诺

- ❌ 不可承诺"运费一定由平台承担"
- ❌ 不可承诺运费补贴的具体金额
- ❌ 不可承诺运费险一定理赔

### 需补充信息

订单号、退换货原因、是否购买运费险。
