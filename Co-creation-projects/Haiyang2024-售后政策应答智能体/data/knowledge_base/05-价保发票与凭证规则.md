# 价保发票与凭证规则

> 业务域：价格保护 / 发票凭证 ｜ 规则前缀：`PRC` / `INV` ｜ 责任部门：商品运营部 / 财务结算部
> 覆盖场景：价格保护、优惠退回、发票开具、发票红冲

---

## PRC-001 价格保护规则

| 规则编号 | PRC-001 |
| 适用场景 | 用户购买后商品降价，要求补差价 |
| 责任部门 | 商品运营部 |
| 时效标准 | 价保期内提出；审核 1–3 个工作日 |
| 关联规则 | PAY-003、PRC-002 |

### 判定标准

| 条件 | 要求 |
|---|---|
| 时间 | 在平台公示的价保期内（通常为签收后 7–15 个自然日，以商品页公示为准） |
| 商品 | 同一商品、同一规格（不同规格视为不同商品） |
| 购买渠道 | 同一平台、同一账号 |
| 降价形式 | **直接降价**可比价；优惠券、满减、限时活动等**通常不参与比价** |

### 不适用价保的情形

| 情形 | 说明 |
|---|---|
| 使用优惠券 / 满减后的到手价 | 属促销行为，不参与比价 |
| 限时秒杀、直播专享价 | 特殊活动价 |
| 不同规格 / 不同型号 | 非同一商品 |
| 已申请退货或已退货 | 转为退货流程 |
| 超出价保期 | — |
| 会员专享价、企业采购价 | 特殊价格体系 |
| 商品已下架或售罄 | 无法比价 |

### 处理流程

1. 核对订单信息与签收时间，确认是否在价保期内
2. 确认降价形式（直接降价 or 促销价）
3. 符合价保条件：核算差价并提交审核
4. 不符合：说明具体依据（哪个条件不满足）
5. 用户有异议：说明规则原文，必要时转人工复核

### 客户沟通要点

- 明确说明价保的适用条件与除外情形
- 不符合条件时，给出**具体原因**而非笼统拒绝
- 若因规则理解差异产生争议，主动提出人工复核

### 禁止承诺

- ❌ 不可承诺"一定能补差价"
- ❌ 不可承诺补差金额（需核算）
- ❌ 不可承诺补差到账时间

### 需补充信息

订单号、签收时间、商品当前价格截图、是否使用优惠。

## PRC-002 优惠券与满减退回规则

| 规则编号 | PRC-002 |
| 适用场景 | 退货退款时涉及优惠券、满减、赠品的处理 |
| 责任部门 | 商品运营部 + 财务结算部 |
| 时效标准 | 随退款流程一并处理 |
| 关联规则 | PAY-003、RET-001 |

### 判定标准

| 情形 | 处理方式 |
|---|---|
| 整单退货，优惠券仍在有效期内 | 优惠券按规则**返还**至账户 |
| 整单退货，优惠券已过期 | 通常**不返还**（以券面规则为准） |
| 部分退货，订单使用了满减 | 退款金额按**优惠分摊**后计算（见 PAY-003） |
| 部分退货，订单未达满减门槛 | 需扣回已享受的优惠部分 |
| 赠品未退回 | 按赠品价值从退款中扣除 |
| 使用了平台补贴 | 补贴部分不退，仅退实付金额 |

### 处理流程

1. 明确退货范围（整单 / 部分）
2. 核算退款金额构成：
   ```
   退款金额 = 商品实付金额 − 优惠分摊 + 运费（按 LOG-005 判定）
   ```
3. 向用户展示明细构成
4. 用户有异议的，提供实付明细与规则依据
5. 仍有异议的转人工复核

### 禁止承诺

- ❌ 不可承诺"优惠券一定返还"
- ❌ 不可承诺"按原价全额退"
- ❌ 不可在核算完成前给出具体金额

### 需补充信息

订单号、退款商品清单、使用的优惠类型、赠品是否退回。

## INV-001 发票开具规则

| 规则编号 | INV-001 |
| 适用场景 | 用户申请开具发票 |
| 责任部门 | 财务结算部 |
| 时效标准 | 申请后 1–3 个工作日开具 |
| 关联规则 | INV-002 |

### 可开具的发票类型

| 类型 | 适用对象 | 说明 |
|---|---|---|
| 电子普通发票 | 个人 / 企业 | 默认类型，开具后发送至预留邮箱 |
| 增值税专用发票 | 一般纳税人企业 | 需提供完整开票资料并审核 |
| 纸质普通发票 | 特殊需求 | 需邮寄，周期较长 |

### 开票要点

| 项 | 要求 |
|---|---|
| 开票金额 | 为**实付金额**（不含优惠券抵扣部分） |
| 开票时间 | 订单完成后可申请 |
| 开票主体 | 通常为商品销售方 |
| 开票内容 | 按商品类目与平台规则确定 |
| 抬头信息 | 需用户准确提供，开错需走红冲流程 |

### 处理流程

1. 确认订单状态（是否已完成）
2. 收集开票信息：抬头类型、抬头名称、税号（企业）、邮箱
3. 提交开票申请，告知开具时效
4. 开具完成后告知查收方式
5. 开具有误的，走 INV-002 红冲流程

### 客户沟通要点

- 主动说明可开票类型与所需信息
- 提醒抬头信息需准确，避免后续红冲
- 增值税专用发票需说明审核要求

### 禁止承诺

- ❌ 不可承诺"马上开好"
- ❌ 不可承诺一定能开具专票（需资质审核）
- ❌ 不可承诺发票金额可与实付金额不一致

### 需补充信息

订单号、抬头类型、抬头名称、税号（企业）、接收邮箱、发票类型。

## INV-002 发票红冲与换开规则

| 规则编号 | INV-002 |
| 适用场景 | 发票信息填错、退货后需冲销、发票丢失 |
| 责任部门 | 财务结算部 |
| 时效标准 | 红冲申请 1–3 个工作日处理 |
| 关联规则 | INV-001、PAY-001 |

### 判定标准

| 情形 | 处理方式 |
|---|---|
| 抬头信息填写错误 | 申请红冲后重新开具 |
| 退货 / 退款完成 | 需配合完成发票红冲（税务要求） |
| 电子发票丢失 | 可申请重新推送 |
| 纸质发票丢失 | 按税务规定处理，通常需用户提供说明 |
| 发票跨月 | 红冲流程更复杂，周期较长 |

### 处理流程

1. 确认红冲原因
2. **退货场景**：说明需先完成发票红冲，退款方可继续
3. 收集红冲所需信息（原发票信息、红冲原因）
4. 提交红冲申请，告知时效
5. 红冲完成后重新开具（如需）

### 客户沟通要点

- 说明红冲属**税务要求**，非平台设障
- 提前告知跨月红冲周期较长
- 退货场景需提前说明"发票未红冲会影响退款进度"

### 禁止承诺

- ❌ 不可承诺"红冲马上完成"
- ❌ 不可承诺跨月红冲的具体完成时间
- ❌ 不可在未完成红冲时承诺退款已可发起

### 需补充信息

订单号、原发票信息、红冲原因、是否需要重新开具。
