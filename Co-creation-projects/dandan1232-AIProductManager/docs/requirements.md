# 需求分析

## 定位与用户

本项目是 Hello-Agents 共创项目中的可运行 Demo，作者为 dandan1232。面向有产品想法、但尚未明确目标用户和功能范围的个人开发者与学习者。用户提供自己的真实想法和回答；系统不要求预先准备知识库或训练语料。

产品形态是网页工作台：左侧访谈，右侧持续更新需求与文档。区别于赛博小镇的角色互动，也区别于直接输入主题生成报告的研究工具，核心是用户的决定持续影响后续分析。

## 用户流程

1. 配置自己的模型连接，可选配置 Tavily 搜索。
2. 输入一个 Idea，AI 从最影响方向的信息开始提问。
3. 每轮回答后更新需求草稿；最多六轮模型澄清，可提前检查草稿并确认。
4. 用户检查或编辑产品名称、目标用户、问题、场景、功能、排除项、约束、成功标准。
5. 用户明确确认后才能生成分析；可选择联网研究或明确跳过竞品部分。
6. 查询少量竞品，评估实现条件，生成带验收条件的 PRD 草稿并复核需求一致性。
7. 查看、导出 Markdown。修改已确认需求后，旧分析和文档失效，需要重新生成。

## 功能与验收条件

| 编号 | 功能 | 可验收结果 |
| --- | --- | --- |
| R01 | 模型与搜索连接 | 支持 OpenAI 兼容模型；密钥不进入接口响应、数据库或 Git；未配置时显示明确错误，不生成伪造结果。 |
| R02 | 逐步访谈 | 模型收到本项目全部访谈和当前草稿；每轮最多一个问题、三个参考选项；六轮后进入确认阶段。 |
| R03 | 需求确认 | 用户可编辑八个字段；至少明确名称与问题；确认内容保存为独立快照，生成流程不能覆盖它。 |
| R04 | 真实竞品研究 | 使用真实搜索接口；最多列出三个竞品；竞品必须引用本次搜索得到的来源编号；保存摘录与查询时间。 |
| R05 | 不完整信息处理 | 搜索无结果或失败时明确提示；不编造竞品。未配置搜索密钥时可由用户关闭联网选项继续。 |
| R06 | 可行性评估 | 给出实现建议、外部依赖、风险、真实用户验证步骤；结论为“可先做原型 / 需先解决依赖 / 信息不足”，不提供虚构成功率。 |
| R07 | PRD 与一致性复核 | 文档包括确认需求、竞品研究、可行性、用户故事、功能与验收条件、非功能建议、实施顺序、待确认项和来源；冲突明确展示。 |
| R08 | 修改与重试 | 修改确认内容清除旧分析和文档；模型失败保留输入；重试不重复追加用户回答。运行中同项目不能提交第二个变更。 |
| R09 | 持久化与导出 | 项目保存到本地 SQLite；刷新/重启后可继续查看；服务中断的任务恢复为可重试；导出真实生成的 Markdown。 |
| R10 | 网页可用性 | 左右工作区、键盘可操作的标签页、可见错误、真实阶段进度；手机端纵向排列；模型输出不作为 HTML 执行。 |
| R11 | 共创交付 | 文件夹按 GitHub 用户名命名，含 README、requirements.txt、main.ipynb、源码、测试及启动说明；提交文件合计小于 5 MB。 |

## 信息边界

- 用户输入与用户确认是需求事实的依据；模型补充的细节都标为建议。
- 搜索摘录提供可追溯线索，不代表已经阅读全文或完成事实审计；来源编号校验不能证明每句话都被原文支持。
- 需求一致性复核由模型执行，可能漏报或误报；报告始终标记为待评审草稿。
- 技术初步可行与商业需求是否成立分别说明。系统不替代真实用户访谈，也不保证项目盈利。
- 测试中的替身只用于自动验证，不会在生产入口展示为真实模型/竞品数据。

## 首版范围

实现文本访谈、确认、竞品摘录、实现建议、Markdown 文档和本地历史项目。作为单机 Demo 运行，不包含账号系统、云同步、语音、付费功能、自动写代码或发布产品。知识库、向量数据库和模型训练不是本版依赖。
