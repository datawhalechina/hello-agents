# BountyTrailAgent：本機貢獻任務與交付追蹤器

> 給同時處理多個開源任務的人：把任務、交付檔、GitHub PR 和平台回執放在同一份本機記憶中，提交前快速檢查是否漏件或檔案已被改動。

## 解決的問題

做多個 Datawhale 共創任務時，任務卡留在平台、程式碼留在 GitHub、ZIP 留在不同資料夾、審核回執又在另一頁。只靠記憶容易重複認領、交錯檔案，或把已改過的 ZIP 當作最後版本。

BountyTrailAgent 是一個小型的本機工具型 Agent，追蹤「一項任務從領取到回執」的證據鏈。它不連接 Datawhale、GitHub 或其他網路服務，也不代替人送出表單；使用者把已知連結與檔案路徑交給它，它就會記錄、比對並提醒缺漏。

## 功能

- 新增任務、列出目前狀態，並記住最近查詢的任務 ID。
- 將已領取任務標記為進行中，讓列表能區分已接案與正在處理的工作。
- 關聯本機交付檔，記錄絕對路徑、檔案大小和 SHA-256；再次檢查時會發現檔案遺失或內容改變。
- 記錄 GitHub PR 與 Datawhale 任務回執連結。
- 送出前檢查「交付檔仍存在且未變更、PR 已記錄」；條件不齊時不會把本機狀態標成已提交。
- 以 JSON 保存任務記憶及多輪對話中的待補資料，關閉程式後仍可接續查詢。
- 使用固定指令與白名單工具，所有狀態變更可追溯；不呼叫 LLM、不需要 API Key，也不會自行執行外部提交。

## 快速開始

需求：Python 3.10 或更新版本。無需安裝第三方套件。

```bash
python main.py demo
```

`demo` 會建立虛構任務和範例檔，示範新增 → 關聯檔案 → 記錄 PR → 檢查 → 標記已提交 → 記錄回執。範例資料只存在暫存目錄，程式結束後會清除。

開始自己的本機工作階段：

```bash
python main.py chat
```

預設資料位置是 `~/.bounty-trail-agent/`。若希望資料保存在專案指定目錄：

```bash
python main.py --data-dir ./local-data chat
```

## 一段實際操作

```text
你：新增
Agent：好，請回覆任務 ID 和名稱，例如：E58 一對一溝通準備。

你：E58 一對一溝通準備
Agent：已記錄 E58「一對一溝通準備」，狀態：已領取。

你：開始 E58
Agent：E58 已標記為「進行中」。

你：關聯 E58 C:\work\E58-submit.zip
Agent：已關聯交付檔 E58-submit.zip（8421 bytes，SHA-256 已記錄）。

你：記錄PR E58 https://github.com/example/course/pull/58
Agent：已記錄 PR：https://github.com/example/course/pull/58

你：檢查 E58
Agent：E58 提交資料齊全：交付檔 E58-submit.zip；PR 已記錄。

你：回執 E58 https://contributor.datawhale.cn/tasks/119
Agent：已記錄平台回執；狀態更新為「審核中」。
```

也支援多輪補資料：先輸入 `新增`，Agent 會記住待補的任務資訊；下一輪再輸入 `E58 一對一溝通準備` 即可建立。

## 指令

| 指令 | 用途 |
| --- | --- |
| `新增 <ID> <名稱>` | 建立任務；重複 ID 不會覆蓋原資料 |
| `開始 <ID>` | 將任務標記為進行中 |
| `列表 [狀態]` | 列出任務；狀態可用 `claimed`、`in_progress`、`submitted`、`under_review`、`accepted` |
| `關聯 <ID> <檔案路徑>` | 計算並記錄本機交付檔的雜湊值，不解析或上傳檔案內容 |
| `記錄PR <ID> <GitHub PR URL>` | 記錄 Pull Request 連結 |
| `檢查 <ID>` | 檢查檔案和 PR；省略 ID 時沿用最近查詢的任務 |
| `提交 <ID>` | 通過檢查後只更新本機狀態，不會送出平台表單 |
| `回執 <ID> <Datawhale 任務 URL>` | 記錄平台回執並標為審核中 |
| `/help` 或 `幫助` | 顯示可用指令；`/quit` 結束對話 |

## Agent 設計

對話入口會把明確指令規劃成一個白名單工具呼叫。工具負責新增、查詢、關聯檔案、驗證提交條件或記錄回執；`LocalMemory` 以原子寫入保存任務資料、事件和最近查詢 ID。這以小範圍展示課程中的工具調用、記憶與多輪互動，並把外部提交保留給使用者本人。

檔案檢查只讀取指定檔案來計算 SHA-256，不解析或上傳檔案內容。記憶檔中的路徑可能包含本機使用者名稱，因此預設放在家目錄，不應將 `local-data/` 加入 Git。

## 專案邊界

- 狀態是使用者維護的本機追蹤資訊，不會自動從網站或 GitHub 同步。
- `已提交` 只代表本機已記錄提交；`審核中` 只在使用者輸入回執後標記，兩者都不能推斷管理員已驗收或已發放獎勵。
- 若附件被移動或重新打包，請再次關聯新檔案；雜湊不符時提交檢查會阻止狀態更新。
- 使用者應自行確認任務要求、審核結果與公開連結。
