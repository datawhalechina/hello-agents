## 模型输入人工复核

这次对可能超过 1K token 的证据输入逐项复核，保留核心任务和有限证据，不将大段文档、失败回复或跨请求历史无条件带入下一轮。使用 UTF-8 字节作离线可执行预算；它不是具体提供方的精确 token 计数，也不覆盖任意用户自定义技能。

| 输入 | 上限与取舍 |
| --- | --- |
| 应用构造的主要模型单项输入 | 9,000 字节；当前问题优先于可选历史。搜索超长问题保留首尾约束，JSON schema 完整保留 |
| PDF、表格、参考书目和查询工具结果 | 6,000 字节；目录保持有效 JSON 并可分页，字段/标题另有限额。片段不能当作论文全文 |
| 图谱候选 | 按实际 JSON 序列化大小分批，逐批独立推理；标注证据只是摘录 |
| 阅读记忆 | 默认 1,200 字节，先预留标签与换行开销，再截取内容 |
| 记忆压缩 | 选择预算内的完整原始条目；未送入模型的条目保留 |
| 格式错误后的重试 | 新建任务 Agent，只保留当前任务和有限纠错说明，避免框架自动重放超长失败输出 |

四个内置技能保持有限的静态正文，先给出名称/描述，由模型按需加载。单项预算不能视为整个多轮模型会话的精确总 token 预算。

## 数据兼容

- 阅读记录自动添加可选 `session_id`，有会话 ID 时累计更新；旧记录和不带 ID 的请求仍按原方式保存。
- 阅读历史自动标记导读行，更新导读时保留普通问答。仅在能核对旧导读内容时接纳旧行。
- 重复保存采用写事务，合并标签、保留未提供的旧字段；清空字段使用明确的更新操作。
- 已经被旧版本覆盖的元数据，以及已合并错误的作者资料，需要原始题录或备份才能恢复。这次不会猜测重建用户数据。

## 在线验收仍需的内容

1. 同一服务商的接口地址、准确模型名及有效密钥。模型需要支持工具调用；无法根据密钥格式确定服务商。
2. 如要验证 Tavily 网页/会议论文集发现，配置对应密钥；其他提供方联系信息和额度配置按实际使用来源补充。
3. 少量可公开访问的真实论文，以及预期问题、引用或比较目标，用于核对搜索相关性、模型证据和技能选择。

真实提供方可用性、模型回答质量、长时间并发负载、扫描件 OCR、私人历史库迁移和各浏览器退出时的实际网络交付尚未验收。阅读时长目前记录页面会话时长，并非精确的活跃阅读时间；跨午夜会话按开始时间归属日期。同步调用到期后结束等待，正在执行的网络调用仍依赖提供方超时收尾。

前端正式构建可能提示依赖分块较大；它是后续加载性能优化项。不要把离线测试通过表述为全部在线效果或所有设备已经验证。
