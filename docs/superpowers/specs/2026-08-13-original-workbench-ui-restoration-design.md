# ResumeAgent 原版工作台界面恢复设计

## 目标

恢复 `/Users/wangzhe/workbuddy-ai/agent/resume-generator/web/index.html` 的核心布局与操作节奏，并接入现有 ResumeAgent FastAPI、SQLite、导师访谈、事实确认、岗位版本、预览和导出能力。新页面应像一款克制、成熟的求职工具，不像 AI 展示页或后台管理系统。

## 产品原则

- 访谈是默认入口和唯一主动作，用户打开页面后无需理解“工作区”概念。
- 智能能力通过问题质量、事实确认和适时反馈体现，不通过机器人头像、发光渐变、大段 AI 宣传文案体现。
- 简历事实、岗位版本和导出继续以服务端 SQLite 为事实来源；浏览器只保存当前选择、折叠状态等无敏感 UI 偏好。
- 保留原页面的紧凑效率，同时让窄屏自然堆叠，避免顶部中文被挤成竖排。
- 已完成的后端和质量评测不回退，界面恢复不等于恢复浏览器直连模型或 localStorage 事实库。

## 方案

采用原生 HTML、CSS 和 JavaScript 工作台，由 FastAPI 同源托管。第一版继续保持无前端构建步骤，便于教程读者直接运行和理解。原单文件中的视觉结构可以复用，但数据访问统一改为模块化 API 客户端。

Streamlit 页面保留为后备入口，不再作为默认产品界面；本轮不删除它。

## 信息架构

### 顶部工具栏

左侧仅显示 `ResumeAgent` 和次级说明“中日英简历工作台”。右侧包含：

- 服务状态：使用普通圆点和“导师可用 / 仅离线功能”，不使用“AI 未配置”作为视觉焦点；
- 当前语言或文档类型；
- 切换语言；
- 示例档案；
- 设置。

“重置”移入设置或更多菜单，避免与高频操作并列造成误触。

### 主工作区

桌面宽屏使用原版双栏：左侧固定宽度的任务面板，右侧弹性简历预览。四个一级标签保持为：

1. `访谈`：聊天记录、下一轮提问、待确认事实、拒绝/确认、暂时想不到；输入框固定在左侧面板底部。
2. `事实库`：候选人基本信息、经历列表、六维证据完成度和已确认事实；默认使用结构化表单，不把 JSON 编辑器作为普通用户主入口。
3. `JD 定制`：创建或选择岗位版本，填写目标公司、岗位与 JD，选择经历并查看证据缺口。
4. `工具`：样式、导出、和暦等低频工具；导师质量评测仍作为开发者命令行能力，不塞进普通用户页面。

右侧始终是当前岗位版本的简历预览。其顶部工具条保留文档切换、样式、编辑和 HTML/Markdown/DOCX/PDF 导出。没有版本或证据时，在预览纸张内部显示简短空状态，不跳转到独立管理页。

### 首次使用

保留原版语言选择弹层，但缩短说明。选定语言后，在访谈面板内完成最小建档：目标岗位、第一段经历和角色。创建后立即进入第一轮提问，不出现仪表盘式中间页。

## 视觉方向

- 背景使用浅灰，面板和简历纸张使用白色；主色沿用低饱和藏青色。
- 只使用细边框、轻阴影和 8–12px 圆角；不使用大面积渐变、玻璃拟态、霓虹光晕或胶囊堆叠。
- 使用系统字体，正文保持 14–15px，信息密度接近原版。
- 按钮文案直接描述动作，例如“开始访谈”“确认事实”“导出 PDF”，不用“让 AI 帮我……”一类营销语气。
- 状态提示只在相关区域出现；服务未配置时不占据整块侧栏。
- 保留原版小闪电作为品牌记号，但不增加机器人、魔法棒、星光等装饰。

## 响应式布局

- 大于 960px：双栏工作台，左侧约 380–420px，右侧占剩余空间，整页高度锁定在视口内。
- 640–960px：上下布局，访谈面板优先，预览保持可滚动的 A4 比例。
- 小于 640px：顶部操作收进“更多”菜单；标签允许横向滚动；输入区保持可见；所有标题保持正常横排。

## 数据与 API

页面启动后依次读取 `/health`、`/capabilities`、`/fact-bases`。浏览器状态只记录当前事实库 ID、经历 ID、会话 ID、版本 ID、语言和标签页。

- 访谈使用现有 session、question、answer、proposal confirm/reject 和 unknown 接口。
- 事实库使用 profile、experience 和 quality 接口。
- JD 定制复用岗位版本的 target role、company、raw JD 和 selected experiences。
- 预览和导出使用现有 version preview/export 接口。
- “编辑”只修改当前岗位版本的手工预览稿；增加服务端版本草稿字段和读写接口，内容保存在 SQLite，不写入统一事实库，也不覆盖已确认事实。
- 所有写操作完成后重新读取服务端对象，不在前端猜测事实库 revision。
- 503 模型不可用时保留回答输入，并给出邻近提示；预览、事实档案和导出继续可用。

需要补充的服务端接口只限于页面真实需要的缺口，不为复刻原单文件而把浏览器本地数据模型重新搬回产品。

## 文件边界

- `resume_agent/web/index.html`：语义结构和静态入口。
- `resume_agent/web/styles.css`：视觉变量、布局和响应式规则。
- `resume_agent/web/api.js`：Fetch API 客户端和错误分类。
- `resume_agent/web/app.js`：页面状态、渲染和事件编排。
- FastAPI 应用负责同源静态资源和 SPA 入口。

文件拆分避免重新形成一个千行以上、数据逻辑与渲染模板混杂的单文件，同时保持零构建工具。

## 错误处理与隐私

- 页面不显示 API Key，也不把 Key 写入 localStorage；模型配置继续由服务端环境变量管理。
- 错误提示转换为用户动作，例如“导师暂不可用，回答已保留”，不直接展示框架堆栈或供应商原文。
- 删除或重置操作必须二次确认；默认恢复动作不删除服务端事实。
- 简历预览使用受控 iframe，手工编辑内容与结构化事实分离并明确标记，避免覆盖事实来源。

## 验收标准

- 与参考页面一样，首屏可直接看到顶部工具栏、访谈面板、输入框和简历预览，不出现深色侧栏。
- 建档、开始访谈、回答、确认/拒绝事实、暂时跳过能在同一左侧面板完成。
- 事实库、JD 定制和工具以原版四标签切换，不跳到独立后台页面。
- 能创建并激活岗位版本、切换语言/样式、预览并导出 HTML、Markdown、DOCX 和 PDF。
- 1440×900、1024×768、390×844 三种视口无文本竖排、横向页面溢出或被遮挡的主要操作。
- 浏览器控制台无错误，API 失败有可恢复提示。
- 现有 Python 测试全部通过；新增静态资源、API 集成和关键浏览器流程测试。

## 非目标

- 本轮不重做简历模板的排版语言。
- 本轮不新增社交登录、云同步、支付或团队协作。
- 本轮不恢复浏览器直连第三方模型和在 localStorage 保存 API Key 的旧实现。
- 本轮不删除 Streamlit 后备入口。
